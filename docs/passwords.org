* Password hashing
:PROPERTIES:
:CUSTOM_ID: password-hashing
:END:

`password-strength` measures a password someone is choosing; `hash-password`
prepares one for storage, and `verify-password` checks a later sign-in against
it. The stored form is a PHC string, the encoding the Argon2 authors specify,
so the cost parameters travel with the hash: raising them tomorrow does not
invalidate anything stored today.

#+begin_src scheme
(use-modules (bewaking password))

(define stored (hash-password #:password "correct horse battery staple"))
;; => "$argon2id$v=19$m=65536,t=3,p=1$..."

(verify-password #:password attempt #:hash stored)   ; => #t or #f
(password-hash? stored)                              ; => #t
#+end_src

| Function          | Arguments                                                      | Returns                     |
|-------------------+----------------------------------------------------------------+-----------------------------|
| ~hash-password~   | =#:password=, =#:memory-kib=, =#:iterations=, =#:parallelism=  | Argon2id PHC string         |
| ~verify-password~ | =#:password=, =#:hash=, =#:max-memory-kib=, =#:max-iterations= | =#t= or =#f=                |
| ~password-hash?~  | =value=                                                        | =#t= for a well-formed hash |

A fresh 16-byte salt is drawn from the system CSPRNG for every call, so hashing
one password twice gives two different strings. Verification reads the recorded
parameters back, derives with them, and compares in constant time. Because a
hash usually arrives from storage or from a client, a recorded cost beyond
=#:max-memory-kib= (default 256 MiB) or =#:max-iterations= (default 16) is
refused rather than obeyed, so a hostile hash cannot ask for the machine's
memory. Everything here needs libgcrypt 1.11 or newer; ask
`argon2id-available?` before relying on it.

The same two operations are available from the shell, which is how a deployment
stores a hash without linking Guile:

#+begin_src shell
HASH=$(./bin/bewaking password hash 'correct horse battery staple')
./bin/bewaking password verify "$HASH" 'correct horse battery staple'  # exit 0
./bin/bewaking password verify "$HASH" 'password'                      # exit 1
#+end_src

* Password strength
:PROPERTIES:
:CUSTOM_ID: password-strength
:END:

A dedicated module, ~(bewaking password)~, measures and generates passwords.
It has no runtime dependency beyond Guile itself.

#+begin_src scheme
(use-modules (bewaking password))

;; Inspect the character classes present in a password.
(password-character-classes "Abc123!") ; => (lowercase uppercase digit symbol)

;; Raw entropy estimate in bits: length * log2(pool size).
(password-entropy #:password "correct horse battery staple") ; => ~131.6

;; A full report: score 0-4, label, entropy, length, classes and feedback.
(password-strength #:password "Tr0ub4dor&3")
;; => ((score . 3)
;;     (label . "strong")
;;     (entropy . 72.27)
;;     (raw-entropy . 72.27)
;;     (length . 11)
;;     (classes lowercase uppercase digit symbol)
;;     (feedback "Longer passphrases are significantly harder to crack."))

;; Convenience predicate; score 3 ("strong") or better passes by default.
(strong-password? #:password "123456")                    ; => #f
(strong-password? #:password "correct horse battery staple") ; => #t
#+end_src

*** Scoring model
:PROPERTIES:
:CUSTOM_ID: scoring-model
:END:

The estimator starts from ~password-entropy~ (length times the base-2 logarithm
of the guessing pool), then applies penalties for:

- membership in a built-in list of common passwords (this forces a score of 0),
- passwords shorter than 8 characters,
- runs of the same character (e.g. =aaaa=),
- ascending or descending sequences (e.g. =abcd= or =4321=).

The penalty-adjusted entropy maps to a score:

| Entropy (bits) | Score | Label       |
|----------------+-------+-------------|
| < 28           |     0 | very weak   |
| 28 - 39        |     1 | weak        |
| 40 - 59        |     2 | fair        |
| 60 - 79        |     3 | strong      |
| >= 80          |     4 | very strong |

This is a practical heuristic, not a formal guarantee of security. A long
passphrase of common words scores highly because it has a large search space,
even though it uses a single character class.

*** Generating strong passwords
:PROPERTIES:
:CUSTOM_ID: generating-strong-passwords
:END:

#+begin_src scheme
(generate-strong-password)                              ; 24 chars, all classes
(generate-strong-password #:length 32)                  ; custom length
(generate-strong-password #:length 16 #:include-symbols #f) ; no symbols
#+end_src

Generation guarantees at least one character from every included class, fills
the rest uniformly, then shuffles the result so there is no positional bias.
The random state is seeded from the platform at module load, giving
unpredictable output across runs.
