* Dependencies
:PROPERTIES:
:CUSTOM_ID: dependencies
:END:

bewaking deliberately keeps its dependency surface small: a recent Guile and
one small helper library for UUIDs. Crypto and encodings are implemented
in-process, so no command-line tool has to be installed or found in =PATH=.
This section documents every dependency, what it is used for, and how to
obtain it.

** Runtime dependencies
:PROPERTIES:
:CUSTOM_ID: runtime-dependencies
:END:

| Dependency     | Minimum | Used for                                                          | Provided by            |
|----------------+---------+-------------------------------------------------------------------+------------------------|
| GNU Guile      |     3.0 | The language runtime, standard library and FFI                    | =guile= in Guix        |
| =guile-uuid=   |     0.9 | Generating the =token-id= (a random UUID v4)                      | =guile-uuid= in Guix   |
| =guile-gcrypt= |     0.5 | libgcrypt bindings: HMAC-SHA256 and strong random bytes; also the | =guile-gcrypt= in Guix |
|                |         | FFI foundation for the AES and PBKDF2 calls described below       |                        |

Nothing else is required. In particular, =openssl=, =xxd= and =base64= are *not*
needed at run time; they are only handy for cross-checking interoperability by
hand (see [[file:primitives.org::#native-cryptography][Native cryptography]]).

*** Note on the wire format
:PROPERTIES:
:CUSTOM_ID: note-on-the-wire-format
:END:

The inner layer of every sealed body is exactly what
~openssl enc -aes256 -pbkdf2 -a -A -k KEY~ produces, and bewaking reads that
format back: an 8-byte salt in a ~Salted__~ header, a 32-byte key and a 16-byte
IV derived with PBKDF2-HMAC-SHA256 over 10000 iterations, and AES-256-CBC with
PKCS#7 padding. Data sealed by the OpenSSL CLI, or by any other implementation
of that format, opens as well. The corresponding reference values live in the
test suite, so the compatibility is checked without needing OpenSSL installed.

The outer, authenticating layer is AES-256-GCM.

** Development and testing dependencies
:PROPERTIES:
:CUSTOM_ID: development-and-testing-dependencies
:END:

These are only needed to develop bewaking, run its tests, or build its docs.

| Dependency        | Used for                                                    |
|-------------------+-------------------------------------------------------------|
| =guile-veritas=   | The test framework and runner                               |
| =guile-json=      | Transitive dependency of =guile-veritas= (reporting)        |
| =guile-fibers=    | Transitive dependency of =guile-veritas= (concurrent tests) |
| =guile-ares-rs=   | Optional nREPL server for the =repl= task                   |
| =guile-documenta= | Generating the technical API documentation                  |
| =texinfo=         | Rendering generated Texinfo docs to HTML                    |
| =watchexec=       | Hot-reloading during development (=dev= / =hr= tasks)       |
| =guix= and =maak= | The reproducible task runner and environment manager        |

All of them are declared in [[file:../manifest.scm][manifest.scm]], so a single Guix
shell is enough to get a complete, reproducible environment.

* Ways to install
:PROPERTIES:
:CUSTOM_ID: ways-to-install
:END:

/Four routes to the same 0.5.0, from the most automated to the most manual.  They all build the tag these documents describe./

** From the Guix channel
:PROPERTIES:
:CUSTOM_ID: from-the-guix-channel
:END:
*GNU Guix* is the functional package manager this project is developed with: a build is a pure function of its inputs, so the same recipe gives the same result everywhere, and an upgrade that goes wrong can be rolled back.

The jointhefreeworld channel carries ~guile-bewaking~ at 0.5.0, so a checkout of the channel is enough — no package definition to write:

#+begin_src shell
git clone https://codeberg.org/jjba23/guix-jointhefreeworld.git
guix install -L ./guix-jointhefreeworld guile-bewaking
#+end_src

Add the channel to ~$HOME/.config/guix/channels.scm~ (the channel's README has the four lines) and a plain ~guix install guile-bewaking~ keeps working on every later ~guix pull~.

** From the Nix flake
:PROPERTIES:
:CUSTOM_ID: from-the-nix-flake
:END:
*Nix* offers the same declarative, reproducible model with its own language, its own store and a binary cache, and it is a natural fit if the rest of your machine is already described in Nix.

The jointhefreeworld flake builds this project with this repository's own expression, so the package cannot drift from the source:

#+begin_src shell
nix build github:jjba23/nix-jointhefreeworld#guile-bewaking
#+end_src

The same attribute is available as an overlay, so ~pkgs.jointhefreeworld.guile-bewaking~ works inside a NixOS or home-manager configuration too.

** As a container image
:PROPERTIES:
:CUSTOM_ID: as-a-container-image
:END:
*Podman or Docker* is the route that puts nothing on the host: the ~Dockerfile~ in this repository builds the project in a builder stage and copies only what it installed into a runtime stage, so the image is small and the host keeps its own toolchain untouched.

#+begin_src shell
podman build -t bewaking .   # docker build -t bewaking . also works
podman run --rm -it bewaking
#+end_src

The image's entry point is Guile, with bewaking on its load path, which makes it useful for a quick try and for reproducing a bug on a clean system.

** As a distribution package
:PROPERTIES:
:CUSTOM_ID: as-a-distribution-package
:END:
*Debian, openSUSE and Arch* each get the project through their own package manager.  Packaging lives in this repository under ~packaging/~ and is pinned to the same release tag, so the recipes and the sources they build are versioned together.

None of the three archives ships bewaking yet, so these are recipes to build rather than packages to install from a mirror:

| Distribution   | Package    | How to build it                                                                     |
|----------------+------------+-------------------------------------------------------------------------------------|
| Debian, Ubuntu | ~bewaking~ | copy ~packaging/debian~ to the repository root, then ~dpkg-buildpackage -us -uc -b~ |
| openSUSE       | ~bewaking~ | ~osc build~ with ~packaging/opensuse~                                               |
| Arch           | ~bewaking~ | ~makepkg -si~ in ~packaging/arch~                                                   |

Each recipe carries its own dependency list, so a missing library fails the build with its name rather than producing a package that cannot load.

** Which one?
:PROPERTIES:
:CUSTOM_ID: which-one
:END:
- *Guix* if you want the toolchain the project is tested with, and the ability to roll back a bad upgrade.
- *Nix* if the rest of your machine is already declarative; the flake pins nixpkgs and gives you a binary cache.
- *Container* if you only want to try the release, or reproduce a report on a machine that has nothing installed.
- *Distribution package* if you want the project managed by the same tool as the rest of your system, with its licence, manual page and launcher in the usual places.

* Installation
:PROPERTIES:
:CUSTOM_ID: installation
:END:

bewaking is developed and consumed with [[https://guix.gnu.org/][GNU Guix]]. The pinned channel
revision lives in [[file:../channels.scm][channels.scm]] and every dependency in
[[file:../manifest.scm][manifest.scm]].

** Enter a complete development environment
:PROPERTIES:
:CUSTOM_ID: enter-a-complete-development-environment
:END:

Enter a shell with all runtime and development dependencies, at the exact
channel revision recorded by the project:

#+begin_src shell
guix time-machine -C channels.scm -- shell -m manifest.scm
#+end_src

** Minimal runtime environment
:PROPERTIES:
:CUSTOM_ID: minimal-runtime-environment
:END:

If you only want to run released code, you need Guile and =guile-uuid= (which
pulls in =guile-gcrypt=):

#+begin_src shell
guix shell guile guile-uuid
#+end_src

** Use it from your own project
:PROPERTIES:
:CUSTOM_ID: use-it-from-your-own-project
:END:

Add bewaking's =src= directory to your load path, then import one or both of its
modules:

#+begin_src scheme
(use-modules (bewaking bewaking))  ; tokens, sealing, permissions
(use-modules (bewaking password))  ; password strength and generation
#+end_src
